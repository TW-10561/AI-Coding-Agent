## 1. 概要（Overview）

本書は、Thirdwave AI Coding Platform の結合テスト（Level 3）仕様を定義する。複数サービスが連携する際の正常系・異常系シナリオを網羅し、API エンドポイントを通じた実際のリクエスト/レスポンスを検証する。

### 1.1 前提条件

- Platform サーバーがテストモードで起動していること（`:3100`）
- SQLite データベースがインメモリモードであること
- Mock vLLM サーバーが起動していること（`:8000`）
- テスト用ワークスペースディレクトリが存在すること

### 1.2 テスト実行

```bash
# Integration tests
bun test platform/tests/integration.test.ts

# With server startup
bun run platform/scripts/start-all.ts &
bun test --filter "integration"
```

## 2. HITL 結合テスト（HITL End-to-End Flow）

### 2.1 HITL 承認フロー完全テスト

```
Test Flow:
 ① POST /api/hitl/evaluate → decision: "ask"
 ② GET /api/hitl/pending → pending request visible
 ③ POST /api/hitl/resolve/:id → "approved"
 ④ GET /api/hitl/stats → approved count incremented
```

| Test ID | Scenario | Steps | Expected | Priority |
|---------|----------|-------|----------|----------|
| HITL-I-001 | 承認フロー完全 | Evaluate(npm install) → Pending → Approve → Stats | Request created → visible in pending → resolved as approved → stats updated | P1 |
| HITL-I-002 | 拒否フロー完全 | Evaluate(npm install) → Pending → Deny → Stats | Request created → resolved as denied → stats updated | P1 |
| HITL-I-003 | 期限切れフロー | Evaluate → Wait > 5min → Check status | Request expires → status: "expired" | P1 |
| HITL-I-004 | 複数同時承認 | 3 evaluates → 3 pending → resolve each | All 3 resolved independently | P2 |
| HITL-I-005 | deny 即時ブロック | Evaluate(rm -rf /) | decision: "deny", no pending request created | P1 |
| HITL-I-006 | allow 即時通過 | Evaluate(echo hello) | decision: "allow", no pending request | P1 |

```typescript
// Example: HITL-I-001
test("HITL-I-001: Full approval flow", async () => {
  // Step 1: Evaluate a medium-risk action
  const evalRes = await fetch("http://localhost:3100/api/hitl/evaluate", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ action: "bash", command: "npm install express" }),
  })
  const evalData = await evalRes.json()
  expect(evalData.decision).toBe("ask")
  expect(evalData.approvalRequest).toBeDefined()
  const requestId = evalData.approvalRequest.id

  // Step 2: Verify pending
  const pendingRes = await fetch("http://localhost:3100/api/hitl/pending")
  const pending = await pendingRes.json()
  expect(pending.some(r => r.id === requestId)).toBe(true)

  // Step 3: Approve
  const resolveRes = await fetch(`http://localhost:3100/api/hitl/resolve/${requestId}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ decision: "approved" }),
  })
  const resolved = await resolveRes.json()
  expect(resolved.status).toBe("approved")

  // Step 4: Verify stats
  const statsRes = await fetch("http://localhost:3100/api/hitl/stats")
  const stats = await statsRes.json()
  expect(stats.approvedCount).toBeGreaterThanOrEqual(1)
})
```

## 12. Mock サーバー仕様

### 12.1 Mock vLLM Server

```typescript
// Mock vLLM that returns tool calls for testing
const mockVLLM = Bun.serve({
  port: 8000,
  async fetch(req) {
    const body = await req.json()
    const msg = body.messages?.at(-1)?.content ?? ""

    // Respond with tool call for "create file" requests
    if (msg.includes("create") && msg.includes("file")) {
      return Response.json({
        choices: [{
          message: {
            role: "assistant",
            content: '<tool_use><name>write_file</name><input>{"path":"test.txt","content":"hello"}</input></tool_use>'
          },
          finish_reason: "stop"
        }],
        usage: { prompt_tokens: 100, completion_tokens: 50 }
      })
    }

    // Default: simple text response
    return Response.json({
      choices: [{
        message: { role: "assistant", content: "Hello! I'm Thirdwave AI." },
        finish_reason: "stop"
      }],
      usage: { prompt_tokens: 100, completion_tokens: 20 }
    })
  }
})
```
