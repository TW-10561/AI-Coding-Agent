## 1. 概要（Overview）

本テスト計画書は、Thirdwave AI Coding Platform の品質保証のためのテスト戦略、スコープ、スケジュール、リソース、および基準を定義する。

### 1.1 テスト対象（System Under Test）

| Component | Technology | Location |
|-----------|-----------|----------|
| Platform API Server | Bun 1.3+ / Hono 4.x | `platform/src/server/` |
| Tool Executor | Bun / TypeScript | `platform/src/services/tool-executor.ts` |
| HITL System | TypeScript | `platform/HITL/` + `platform/src/services/hitl-service.ts` |
| Policy Engine | TypeScript | `platform/src/services/policy-engine.ts` |
| Provider Registry | TypeScript | `platform/src/services/provider-registry.ts` |
| Task Queue | TypeScript | `platform/src/services/task-queue.ts` |
| Audit Logger | TypeScript | `platform/src/services/audit-logger.ts` |
| VS Code Extension | TypeScript / Webview | `platform/vscode-extension/` |
| TUI Client | TypeScript / Ink | `platform/tui/` |
| Skills System | JSON / TypeScript | `platform/skills/` |

### 1.2 テスト目的（Objectives）

1. 全APIエンドポイントが仕様通りに動作すること
2. HITLセキュリティガードが全リスクレベルで正しくトリガーされること
3. ツール実行（bash, write_file, read_file, etc.）が安全に実行されること
4. LLMプロバイダー統合が正しく動作すること
5. VS Code Extension が HITL 承認 UI を正しく表示すること
6. パフォーマンスがSLAを満たすこと（API応答 < 500ms, ツール実行 < 30s）
7. セキュリティポリシーがバイパスされないこと

| Metric | Target |
|--------|--------|

| System test pass rate | ≥ 95% |

### 5.2 非機能テスト

| Metric | Target |
|--------|--------|
| API response time (p95) | < 500ms (non-inference) |
| Tool execution timeout | < 30s (default), < 120s (max) |
| HITL polling latency | < 3s from creation to extension display |
| HITL approval response | < 2 min (before expiry) |
| Concurrent requests | ≥ 10 simultaneous chat sessions |
| Memory usage | < 512MB steady state |

| Metric | Target |
|--------|--------|
| HITL bypass attempts | 0 successful bypasses |
| Path traversal attempts | 0 successful traversals |
| Command injection attempts | 0 successful injections |
| Policy enforcement accuracy | 100% |
| Sensitive file detection | 100% for defined patterns |

## 6. リスクと対策（Risks and Mitigations）

| Risk | Impact | Mitigation |
|------|--------|------------|
| vLLM unavailable | Cannot test chat/tool flow | Mock vLLM server for integration tests |
| Flaky tests due to timing | False failures | Use deterministic mocks, generous timeouts |
| HITL polling race conditions | Missed approvals | Test with controlled timing, verify server-side poll |
| Cloud provider rate limiting | Integration test failures | Use recorded responses, test in isolation |
| Extension headless testing | UI not fully testable | Use VS Code extension test runner + manual UAT |
