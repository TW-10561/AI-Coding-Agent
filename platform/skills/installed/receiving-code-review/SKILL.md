# Receiving Code Review

Techniques for receiving code review feedback productively and improving as a developer.

## Mindset for Code Review

### Growth Perspective
- See feedback as improvement opportunity
- Learn from experienced reviewers
- Develop pattern recognition
- Expand your skill set
- Collaborate towards best solution

### Separating Code from Self
- Review is about code, not you
- Criticism improves code quality
- Feedback is professional, not personal
- Everyone receives feedback
- Experts ask for help

## Understanding Feedback

### Feedback Categories

**Blocking Issues** (Must address)
- Security vulnerabilities
- Test failures
- Breaking changes
- Design conflicts

**Important Issues**
- Performance concerns
- Maintainability problems
- Best practice violations
- Consistency issues

**Nice-to-Haves**
- Style preferences
- Alternative approaches
- Documentation improvements
- Code organization

### Clarifying Comments

If feedback is unclear:
- Ask specific questions
- Request examples
- Discuss in pair call if needed
- Don't assume intent

## Responding to Feedback

### Positive Feedback
- Acknowledge appreciated insights
- Thank for suggestions
- Note for future reference
- Ask for more detail if interested

### Critical Feedback
- Listen without reacting defensively
- Consider the perspective
- Ask for clarification
- Take time to respond (not immediately)

### Disagreement
1. Understand their perspective fully
2. Explain your reasoning
3. Provide data/examples if possible
4. Ask for input from others
5. Reach compromise if possible
6. Document decision

## Response Patterns

### Accepting Criticism
"Good point! I'll [action]"
"I didn't consider that. Let me [improve]"
"Thanks for catching that edge case"

### Requesting Clarification
"Could you explain what you mean by [concept]?"
"Do you have an example of what you're suggesting?"
"Should I apply this everywhere or just here?"

### Discussing Alternatives
"I chose [approach] because [reason], but I see your point about [concern]"
"Would [alternative] work better in this case?"
"Let me implement [suggestion] and test it"

## Not All Feedback is Equal

### Accept Feedback About
- Bugs and errors
- Security issues
- Performance problems
- Test coverage
- Documentation
- Consistency

### Question Feedback About
- Personal coding style
- Subjective naming
- One-off edge cases
- Premature optimization
- Bike-shedding

## Implementation Approach

1. Group feedback by category
2. Address blocking issues first
3. Ask clarifying questions before implementing
4. Implement changes systematically
5. Run full test suite
6. Request re-review
7. Respond to all comments

## Learning from Feedback

### Track Patterns
- What feedback repeats?
- What mistakes happen frequently?
- What areas need improvement?

### Improve Systematically
- Study identified weak areas
- Practice specific skills
- Request focused reviews
- Measure improvement

### Share Knowledge
- When you learn something, teach it
- Document patterns you discover
- Help others avoid same mistakes

## Difficult Feedback Scenarios

### When Reviewer is Wrong
- Explain your understanding
- Provide references/evidence
- Propose running experiment
- Escalate if necessary
- Be open that you might be wrong

### When Feedback Conflicts
- Document both perspectives
- Ask for tie-breaker opinion
- Suggest trying both approaches
- Make decision and move forward

### When Reviewer is Harsh
- Assume best intent
- Sleep on it before responding
- Discuss offline if very upset
- Involve team lead if problematic
- Preserve psychological safety

## Feedback for All Skill Levels

### Junior Developers
- Feedback is more frequent and foundational
- Focus on fundamentals
- Build good habits early
- Ask "why" questions

### Mid-Level Developers
- Feedback focuses on design and patterns
- Learning architectural decisions
- Expanding depth in domains

### Senior Developers
- Feedback on architectural decisions
- Strategic choices
- Mentoring approach
- Team impact

## Feedback Tools

- Use GitHub suggestion feature
- Commit message references
- Draft mode for WIP feedback
- Individual conversations when needed

## Building Review Culture

- Be gracious with feedback
- Thank reviewers
- Close review loop quickly
- Help others with their code
- Celebrate improvements
